# Weekly Operating Rhythm

A light cadence one person can run with AI assistance. Keeps state fresh, prevents drift, and measures whether the system improves outcomes.

---

## Monday — Plan (15–20 min)
1. Read `state/CURRENT_STATE.md`; set the week's strategic priority and sprint theme.
2. Review open decisions and blockers; assign next actions with dates.
3. Confirm 1–3 weekly commitments (small, verifiable).

## Midweek — Execute
- Run the relevant pipelines (role or consulting). Load only the skills each task needs.
- Apply the Quality Check at the review threshold.
- Append observations to the Learning Ledger as they occur (don't batch from memory later).

## Friday — Review & Measure (20–30 min)
1. Update Current State (stages, next actions, blockers).
2. Review the Learning Ledger: promote matured patterns (Emerging→Class 1, Repeated→Class 2 experiment).
3. Check Experiment Register against pre-registered criteria; close or iterate.
4. Record material decisions in the Decision Register.
5. Triage the Amendment Queue; nothing reaches Tony without a Quality Check.
6. Read the **system-improvement KPIs** (Experiment Register): discovery yield, false-positive rate, response/interview conversion, scoring calibration, consulting funnel, governance health. Are decisions getting better, not just busier?

## Monthly — Calibrate
- Sweep dead sources and weak queries (Class 1).
- Re-verify time-sensitive facts on active items (freshness rule).
- Decide whether any Repeated pattern is ready for a Class 3 proposal.

## Drift guard
If an artifact or recommendation conflicts with the Constitution, **stop** and use the precedence order (`GOVERNANCE.md` §1). Learning Ledger observations never override the Constitution.
