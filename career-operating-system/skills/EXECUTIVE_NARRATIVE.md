# Executive Narrative

**Primary mandate:** Turn Tony's verified experience into credible executive positioning — the approved, evidence-bound story that downstream materials must not exceed.

**Required inputs:** Tony's record; the target archetype or buyer problem; relevant fit/diligence outputs.

**Required outputs:** an approved narrative map — problems solved, value mechanisms, why-AI-is-the-logical-next-chapter, differentiation from sales/alliances/ops/training leaders, revenue **influence** framing (never ownership), with each claim truth-labeled and a "do-not-overstate" boundary list.

**Explicit boundaries (does NOT):** write the résumé/outreach itself (→ `application-materials`); fabricate or upgrade claims; produce public POV (→ `pov-thought-leadership`).

**Handoffs:** upstream ← `role-fit-evaluation` / `consulting-practice-architect`; downstream → `application-materials`, `interview-intelligence`, `networking-and-sponsorship`.

**Evidence requirements:** every positioning claim is Résumé-supported or stronger; influence ≠ ownership enforced; scale/team/authority stated only as evidenced. The narrative map is the **ceiling** for all downstream copy.

**Write permissions:** `state/CURRENT_STATE.md` (active positioning hypothesis); `state/LEARNING_LEDGER.md` (which framings land); `state/AMENDMENT_QUEUE.md` only if positioning implies a thesis change.

**Stop / escalate when:** a compelling story requires an unsupported claim → stop, downgrade to the defensible version; a new positioning would shift the thesis → Class 2/3.

**Quality Check:** required (changes positioning; contains experience claims).

## Method
1. Extract mechanisms and outcomes from evidence, not adjectives.
2. Build the throughline: problem → system built → decision influenced → measurable result.
3. Frame AI as a logical extension of demonstrated capability.
4. Mark every claim's label and set explicit overstatement boundaries.
