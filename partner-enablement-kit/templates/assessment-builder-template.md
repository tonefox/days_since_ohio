# Assessment Builder Template

> **Instantiation layer / template.** A reusable skeleton for building a **demonstration-based**
> assessment for any competency in the sales or technical maps. Copy this file per competency and
> fill it in. It is designed so a non-specialist can produce a credible assessment without
> instructional-design expertise (important for Path B).

This template operationalizes **Article V (Demonstrated Competency)**: certification is by
performance under realistic conditions, not recall. Every field below exists to make the
demonstration realistic, fair, and consistently scored.

## 2. Scenario

Describe a realistic situation in which the competency must be performed. Keep it specific to your
organization's vertical and product context (brand via `brand.yaml`).

- **Context:** `____`
- **The partner's task:** `____`
- **Constraints / complications:** `____` (raise these to reach Practitioner or Advisor difficulty)
- **What the partner is given:** `____` (inputs, data, tools — including AI tools if relevant)

## 3. Form of demonstration

Choose how competence is shown. Pick the lightest form that still proves the capability.

- [ ] Live role-play / simulated customer interaction
- [ ] Produced artifact (e.g., qualification rationale, business case, architecture, demo plan)
- [ ] Worked scenario / lab exercise
- [ ] Real-world artifact from actual work (with sensitive data removed)

## 4. Scoring rubric

Define observable criteria. Score each as **Not yet / Approaching / Meets / Exceeds**. The
partner must **Meet** every criterion at the target tier to certify.

**Tier calibration note:** the *same* competency can be assessed at different tiers by adjusting
scenario complexity (Section 2) and rubric stringency, not by changing the competency. Advisor

## 5. AI-fluency check (where applicable — Article VI)

If the competency involves AI use (e.g., S6–S8, T6–T8), or if AI tools are available during the
demonstration, assess responsible use explicitly:

- Did the partner use AI effectively to accelerate the task? `____`
- Did the partner **critically evaluate** AI output rather than accept it uncritically? `____`
- Did the partner stay within responsible-use and data-handling guardrails? `____`

## 6. Administration

- **Who administers/scores:** `____` (trainer in Path A; local owner or AI in Path B; AI at
  maturity L3+)
- **Time allowed:** `____`
- **Calibration:** if multiple assessors, how is scoring kept consistent? `____`

## 7. Record

On a Meet/Exceed result, record: partner, competency ID, tier achieved, date, evidence reference.
This record feeds **adaptive pathing (Article IV)** — it is what prevents re-teaching proven
capabilities — and rolls up to the **outcome signal** in Section 1 for **accountability (Article
VIII)**.

---

### Using AI to build the assessment itself
At maturity L1+, use AI to draft Sections 2–4 from the competency definition, then exercise human
judgment to ensure the scenario is realistic and the rubric is fair. This is the fastest way for a
Path B organization to stand up credible assessments without an instructional-design team.
